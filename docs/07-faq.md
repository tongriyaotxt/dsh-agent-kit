# 07 · FAQ

## 为什么要单独一个仓库，而不是在每个项目里复制粘贴 30 行？

因为「30 行」里有一半是**踩过的坑的补丁**：`.cmd` 包装、stdin 传参、stderr 分流、超时 kill、环境变量摘除、chunked SSE。复制粘贴时最容易漏掉第 5 项，然后就出现「偶发串进别人的会话」这种极难复现的故障。协议 + 参考实现 + 离线回归用例放一处，各项目引用它。

## 为什么不直接做 SDK（pip install / npm i）？

协议边界只有一个进程，SDK 只是给 `Popen` 套壳。套壳带来的收益（少写 30 行）小于成本（多语言各一份 bug + 版本对齐 + 用户看不懂黑盒）。本仓库给的是**可复制的源码**：直接 `cp python/dsh_agent_kit` 到你项目里就行，不需要安装。

## 为什么不让 dsh 常驻、一次启动多次调用？

`headless` 的语义就是「一次任务、一个进程、退出」。要长会话就靠 `--session-id` 续接：**进程是新的，会话是老的**。这样每次故障都被进程边界隔离，不会出现「跑了两天的进程状态错乱」。冷启动 1–3 秒，对绝大多数交互无感。

## 能用 WebSocket 吗？

能，但没必要。SSE 是单向流，够用；WebSocket 要自己处理心跳、断线重连、帧协议。真要中途注入指令，正确做法是**取消当前请求 + 带同一 `session_id` 发新任务**（[05](05-server-side.md#六替代传输)）。

## 前端能直接调 dsh 吗？

不能。浏览器不能 spawn 进程。必须有一个同机后端（本仓库 gateway 就是最小的那个）。

## headless 缺 plan/goal/todo，长任务怎么办？

应用侧编排：把长任务拆成多个 headless 调用，中间结果落文件，会话 id 串起来。这比指望 headless 有任务状态机更可控 —— 状态在**你的**代码里，不在黑盒里。

顺带一个真实约束：headless **没有上下文压缩**（compaction）。所以单轮别塞巨型输入，超长内容让它自己 `fs` 读，而不是拼进 prompt。

## 怎么控制成本？

三件事：

1. **精简 profile**：不用的插件目录越短，系统提示越短；
2. **MCP 只开必需**：一个 `screen-use` 就能让 `inputTokens` 从 169 涨到 1.8 万；
3. **复用会话**：`cacheReadTokens` 上涨说明吃到缓存了，单价更低。

把 `status.step_end.usage` 落库，按任务聚合，成本就可见了。

## 能并行跑多个任务吗？

能，一任务一进程。注意三点：并发上限（信号量）、每任务独立 `cwd`（避免互相踩文件）、**同一个 `sessionId` 不要并发**（会话是串行状态）。

## 换模型要改接入层吗？

不用。模型在 profile 的 LLM 插件配置里，接入层只认 `--profile`。这也是要用专用 profile 的原因：模型换代只改 profile，不改代码。

## Linux / macOS 能用吗？

能。协议与平台无关；`cmd /c` 分支只在 Windows 触发，其他平台直接 exec。Node 侧把 `shell` 设成 `process.platform === "win32"`。

## 输出里偶尔有非 JSON 行怎么办？

极少，但存在（例如某个插件往 stdout 打了日志）。客户端降级成 `{"type":"_raw"}` 事件保留原文，不中断流。真遇到频繁发生，说明有插件污染 stdout —— 用 `--dump-config` 找出来关掉。

## 能不能拿到「正在调用哪个工具」？

能，`tool` 事件里有，但字段随版本变化。**按原样透传给 UI**，不要假设结构，展示时只取你能识别的部分（一般是工具名）。

## 为什么 `dsh headless` 和 `dsh --profile headless` 都在文档里出现？

两者等价（`dsh [--profile] <name>`，名字可省 `--profile`）。本仓库统一用 `--profile headless`，因为要加 `--patch` 时这个写法更不容易搞错顺序。

## 这个仓库和 dsh 是什么关系？

独立社区工具，不隶属于 dsh 项目。它只依赖 dsh 的**公开 CLI 行为**（`--json` 事件流），不反向工程内部 API，所以升级风险小。协议不对时 `tests/conformance.py --live` 会先报出来。

## 我要提交改动

见 [CONTRIBUTING.md](../CONTRIBUTING.md)。核心要求一条：**新断言必须先能在 `tests/` 里离线复现**，纯 live 的行为不进 CI。
